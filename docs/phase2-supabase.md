# Phase 2 設計メモ：Supabase への送信と再送

作成日: 2026-10-16

## 決めたこと

| 項目 | 決定 |
|---|---|
| API | FastAPI + SQLite をやめ、Supabase（Postgres + 自動 REST API）にした。サーバを置く場所が要らず、無料枠でデータも消えない。推定は Postgres の関数で行う（`supabase/README.md`） |
| 認証 | ノードはヘッダ `x-node-token`。Supabase では Authorization が JWT 用なので独自ヘッダにした。どのリクエストにも `apikey: <publishable key>` が要る |
| 公開範囲 | publishable key で読めるのは集計値のテーブルと RPC だけ。nodes（トークンのハッシュ）は読めない。書き込みは RPC 経由のみ |
| 送る値 | 窓の集計値から `devices`・`adv_count`・`estimated_people` を除いたもの。部分的な窓は送らない |
| 送信キュー | Room（`upload_queue.db`）。確定した窓をまず保存し、成功したら消す。Service や端末を再起動しても残る。上限は1週間分（10,080件）で、超えたら古いものから捨てる |
| 送信の間隔 | 前回の送信から設定の送信間隔（既定60秒）が経っていれば、窓の確定時にキューの古い順に最大100件をまとめて送る |
| 失敗の扱い | 通信失敗・5xx・401/403/404/408/429 はキューに残し、次の窓で再送する（トークンや URL の誤りは設定を直せば送れるので捨てない）。それ以外の 4xx（中身の誤り）は捨てる。サーバは同じ `(node_id, observed_at)` を重複として無視するので、二重に保存されることはない |
| ノード ID の変更 | 送信器を作り直すとき、ほかのノード ID の未送信分を捨てる（新しいトークンでは受け付けられず、キューが詰まるため） |
| 既定値 | Supabase の URL と publishable key は `build.gradle.kts` に書いてある（公開してよいキー）。ノード ID とトークンは `android/local.properties` の `NODE_ID` / `NODE_TOKEN` から読み、未設定なら設定画面で入れる |
| Ambient | 動作確認用の送信はそのまま残した（設定で ON/OFF） |

## 実機での確認（Pixel 9a、2026-10-16）

ノード `room-1-01`（教室 `room-1`）として送信した。

| 項目 | 結果 |
|---|---|
| 窓の確定から約1秒で送信される | OK。23:09 の窓を 23:10:01 に送信し、HTTP 200 `created: 1` |
| 部分的な窓を送らない | OK。インストール直後の 23:08 の窓は送られていない |
| 通信断からの再送 | OK。モバイルデータを 23:16〜23:19 に切断。23:17・23:18・23:19 の送信はキューに残り（DNS 解決の失敗）、23:20:01 に4件まとめて送信して `created: 4` |
| 機内モードでの試験 | 参考にならない。機内モードでは Bluetooth も切れるため、スキャン自体が止まり、窓が欠ける |

## Pixel 7a の追加（2026-10-16）

- ノード `room-1-02`（教室 `room-1`）として導入。23:35 の窓から送信できている
- 7a には Mac で署名したアプリが入っていて上書きできなかったため、アンインストールした。端末内ログ（10/8〜10/12、10/16）は事前に `Documents/crowd-level_checker_logs/pixel7a-backup-2026-10-16/` へ退避した。7a ではログがアプリ内部の領域（`files/logs`）にあり、`adb shell run-as com.crowdlevel.node` でしか読めなかった
- 同じ時刻に Pixel 9a（`room-1-01`）は 23:19 の窓から受信0台が続いている（送信は続いている）。9a は触らずに置いているので原因は未調査
- 同日、ユーザーの判断で Supabase から 9a のノード `room-1-01` とその観測値（45件）を削除し、7a だけにした。削除前の観測値は `Documents/crowd-level_checker_logs/supabase-room-1-01-backup-2026-10-16.jsonl` に退避した。9a 本体はそのままで、送信は 403 で拒否される（9a の端末内キューに溜まる）
